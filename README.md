# Sprint_7 — API-тесты Яндекс Самоката

Обязательная часть финального проекта: Python, requests, pytest, Allure.
Документация сервиса: https://qa-scooter.education-services.ru/docs/

## Покрытие

| Ручка | Проверки | Количество |
| --- | --- | ---: |
| Создание курьера | Успешное создание, дубликат, занятый логин с другими данными, отсутствующие и пустые поля | 8 |
| Логин курьера | Успешный вход с id, отсутствующие, пустые и неправильные поля, несуществующий пользователь | 8 |
| Создание заказа | BLACK, GREY, оба цвета, пустой список цветов, отсутствие поля color | 5 |
| Список заказов | Код ответа, массив заказов, элементы списка и пагинация | 1 |

Каждая ручка проверяется отдельным классом. Цвета и негативные проверки параметризованы.
Тесты проверяют код и тело ответа. HTTP-запросы сосредоточены в `api/`.

## Запуск

Нужны Python 3.10+ и доступ к учебному API. Браузер не требуется.
Выполните из папки проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest
```

Для воспроизведения проверенного окружения используйте `requirements-lock.txt`.
Адрес API можно задать переменной окружения `SCOOTER_BASE_URL`.
Таймаут подключения — 5 секунд, ожидания ответа — 20 секунд.

## Независимость и очистка данных

- Для каждого теста генерируется уникальный логин курьера с UUID.
- Фикстуры удаляют созданных курьеров после теста, включая упавшие проверки.
- Номера созданных заказов сохраняются и используются для отмены в teardown.
  В API нет ручки удаления заказа; используется отмена через query-параметр `track`.
- Ошибка очистки данных явно приводит к ошибке teardown.
- Данные заказов синтетические, дата доставки — текущая дата + 2 дня.

## Результаты проверки 18.11.2026

Выполнены 22 теста: **20 passed, 2 failed**, 23,90 секунды. Ошибок очистки данных нет.
В Allure: 20 Passed, 1 Failed и 1 Broken (таймаут запроса).

Два расхождения с документацией сохранены как реальные падения:

1. **Создание курьера без `firstName`.** В таблице параметров документации поле
   отмечено обязательным. Тест ожидает 400, API возвращает 201 и `{"ok": true}`.
   При этом пример ошибки в документации упоминает только login и password:
   обязательность firstName требует уточнения.
2. **Вход без поля `password`.** После создания курьера отправляется JSON только
   с его login. По документации ожидается 400 и сообщение «Недостаточно данных
   для входа». Ответ не приходит за 20 секунд, возникает ReadTimeout.
   Запрос с явно переданным пустым паролем возвращает ожидаемые 400 и сообщение.

Оба случая воспроизведены в двух прогонах. Ожидания в тестах не заменены на
ошибочное фактическое поведение и не скрыты через skip/xfail.
Для повторного запуска только этих проверок:

```powershell
.\.venv\Scripts\python.exe -m pytest "tests/test_create_courier.py::TestCreateCourier::test_create_courier_without_required_field_returns_bad_request[firstName]" "tests/test_login_courier.py::TestLoginCourier::test_login_without_required_field_returns_bad_request[password]"
```

## Allure

Результаты находятся в `target/allure-results`, готовый отчёт — в `allure-report`.
В отчёт включены параметры HTTP-запросов, коды и тела ответов, шаги подготовки
и очистки. Пароли во вложениях относятся только к временным тестовым курьерам,
которые удаляются после теста.

Для генерации Allure 3 нужны Node.js 22+ и npm:

```powershell
npx allure generate target/allure-results --config allurerc.json --output allure-report --clean
```

Откройте `allure-report/index.html` в браузере: отчёт самодостаточный, отдельный
сервер не нужен. В Git добавлена папка с результатами, остальные файлы из target игнорируются.
Новый запуск pytest очищает предыдущие результаты; после выборочного запуска
нужно выполнить весь набор, чтобы отчёт снова содержал все 22 проверки.

## Postman

Коллекция `postman/Sprint_7.postman_collection.json` содержит 8 базовых запросов
и 16 проверок. Коллекция выполнена через Newman: все проверки прошли.
Перед написанием тестов также выполнены отдельные HTTP-запросы для знакомства с API.

Для ручного повторения импортируйте коллекцию в Postman и запустите все запросы
по порядку. Последние два запроса отменяют созданный заказ и удаляют курьера.
Для запуска коллекции из терминала:

```powershell
npx newman run postman/Sprint_7.postman_collection.json --timeout-request 20000
```

## Структура и сдача

`api/` — HTTP-клиент и методы API; `tests/` — классы тестов; `data.py` — генерация
данных и ожидаемые сообщения; `conftest.py` — фикстуры и очистка.

В `main` находится начальный README, проект выполнен в `develop`.
Для сдачи используется Pull Request из `develop` в `main`; его ссылку нужно
отправить в тренажёр и оставить PR открытым до завершения проверки.
